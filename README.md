# xx.hocon

Shared test resources for HOCON parser conformance testing across [rs.hocon](https://github.com/o3co/rs.hocon), [ts.hocon](https://github.com/o3co/ts.hocon), [go.hocon](https://github.com/o3co/go.hocon), and [py.hocon](https://github.com/o3co/py.hocon).

## Implementation status

Per-implementation compliance rates and per-item status live in [docs/compliance-matrix.md](docs/compliance-matrix.md). Release notes are in each implementation's `CHANGELOG.md` and GitHub releases ([ts.hocon](https://github.com/o3co/ts.hocon/releases), [go.hocon](https://github.com/o3co/go.hocon/releases), [rs.hocon](https://github.com/o3co/rs.hocon/releases), [py.hocon](https://github.com/o3co/py.hocon/releases)). This README does not copy those figures, so it cannot fall behind them.

**Ecosystem conformance:** fixture-pass results for the JVM-free HOCON libraries across five languages, measured against the same Lightbend-generated fixtures — [docs/ecosystem-conformance.md](docs/ecosystem-conformance.md). The harness is in [`ecosystem-bench/`](ecosystem-bench/).

## Structure

- `testdata/hocon/` — Lightbend HOCON test suite `.conf` files (master copy)
- `expected/hocon/` — Expected JSON output generated by the Lightbend reference implementation (typesafe-config)
- `testdata/format-ingestion/` — Differential fixtures for the format adapters (env / JSONC / TOML / YAML / Properties). No Lightbend oracle exists for these, so the expectations encode the project's own F-item decisions ([docs/format-ingestion-mapping.md](docs/format-ingestion-mapping.md)) and are driven by `manifest.json` — see [docs/fixture-conventions.md](docs/fixture-conventions.md#format-ingestion-fixtures-f-items--the-format-adapters)
- `generate/` — Java tool to regenerate expected JSON from conf files
- `docs/` — the three item namespaces and their roll-ups: [spec-checklist.md](docs/spec-checklist.md) (`S`, canonical Lightbend items), [extra-spec-conventions.md](docs/extra-spec-conventions.md) (`E`, cross-impl behaviour outside the spec), [format-ingestion-mapping.md](docs/format-ingestion-mapping.md) (`F`, how foreign formats map onto the value model), plus [compliance-matrix.md](docs/compliance-matrix.md), [fixture-conventions.md](docs/fixture-conventions.md) and [harvested-corpus.md](docs/harvested-corpus.md)

## Usage

Parser repos fetch testdata via:

```bash
make testdata
```

This downloads the latest testdata and expected JSON from this repo.

## Regenerating Expected JSON

Requires Java 17+:

```bash
cd generate
./gradlew run
```
