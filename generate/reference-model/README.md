# generate/reference-model — expectation generator for E23 / o3co fixtures

**This is not a fifth HOCON implementation.** It is a small Python model of
[`docs/resolution-model.md`](../../docs/resolution-model.md). Its one job is to write the expected file of a
fixture whose answer is an **E23 / o3co decision**, which no oracle provides.

- **Lightbend-aligned cases always come from Lightbend.** Their expected files are written by
  `GenerateExpected` (`make generate`). A case is Lightbend-aligned when `GenerateExpected.java` lists it.
- **The model only handles cases with a `<name>.expectation.md` sidecar.** The sidecar sits next to
  the case's `.conf` under `testdata/hocon/`, and it names the E23 rule or the resolution-model §11
  decision behind the expectation.
- **The generator refuses** to write for any case that `GenerateExpected.java` lists, and exits
  non-zero. A case is therefore never generated by both.
- **The model is not a parser of record.** It parses only the HOCON subset the fixtures use: objects,
  dotted keys, `=` / `:` / `+=`, lists, quoted and unquoted strings, numbers, substitutions,
  concatenation and `include "file"`. Do not use it to settle anything Lightbend can answer.

## Run

From the repository root:

```sh
make generate-model                                          # write expected/hocon/<group>/<name>-expected.json or <name>.error
python3 generate/reference-model/generate_model.py --check   # CI-style: fail if any expected file would change
python3 generate/reference-model/resolution_model.py some.conf   # print the model's result for one file
```

It needs `python3` (3.8 or later) and the standard library only.

## The sidecar

`<name>.expectation.md` holds one `key: value` line per field, followed by free text:

| field | meaning |
| --- | --- |
| `kind` | `e23-order`, `e23-view-reentry`, `e23-memo`, `o3co-J1` … `o3co-J5`, or `pending-step-b` |
| `lightbend-1.4.9` | Lightbend's result (for the record; `ERR` for an error) |
| `e23-final` | `pending-step-b` only: the E23 final value, which becomes the expected file |
| `interim` | `pending-step-b` only: the value this step produces (`ERR` or JSON). The generator checks the model still gives it. |

What the generator writes:

- **`pending-step-b` cases:** the expected file is the `e23-final` value. The implementations produce the
  `interim` value until window step (b) adds E23 rule 1, and mark the case pending until then.
- **Error results:** a `.error` sidecar whose `Exception class:` line names the reference model
  instead of a Lightbend class. Conformance runners only check that the case errors
  (see [`docs/fixture-conventions.md`](../../docs/fixture-conventions.md)).

## Keeping it honest

- When `docs/resolution-model.md` changes, change `resolution_model.py` in the same PR and run
  `make generate-model`.
- The model was checked against Lightbend 1.4.9 on the window corpus (248 cases). It agrees on every
  case except the classified E23 / o3co ones. The classification is in the PR that added this directory.
- A case the model and Lightbend disagree on, but that no E23 rule or §11 decision explains, is a bug
  in the model. Fix the model; do not add an `.expectation.md` for it.
